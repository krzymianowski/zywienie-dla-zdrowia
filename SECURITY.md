# Security Policy

## Development status

The project has not published a stable release. A dedicated private vulnerability-reporting channel will be established before the first stable release, so there is currently no supported-version matrix or public security contact.

## Responsible reporting

Do not publish vulnerability details in a public issue, discussion, pull request, or other public channel before a fix and coordinated disclosure are ready. Until the dedicated reporting mechanism is available, a reporter may open a public issue containing only a request for a private contact channel and no technical details that could expose users.

A useful private report should eventually include:

- the affected version or revision;
- clear reproduction steps and expected impact;
- a minimal proof of concept that does not contain sensitive real-world data;
- any suggested mitigation, if available.

Never place credentials, access tokens, patient or employee data, real deployment paths, private documents, or identifying information about a real medical facility in a report. Use fictional, minimal examples only.

Reporters should allow maintainers a reasonable opportunity to investigate, prepare a fix, and coordinate disclosure. The permanent responsible-reporting process will be documented here before the first stable release.
